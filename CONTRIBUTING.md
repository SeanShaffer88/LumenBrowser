# Contributing

Follow Mozilla's [contributor workflow](https://firefox-source-docs.mozilla.org/contributing/contribution_quickref.html), source conventions, Fluent localization, and native build/test tooling. Keep fork patches small. Explain the consumer, user benefit, privacy impact, security consequence, performance cost, and upstream maintenance cost of a new default or feature. Keep imported sources and their notices intact.

Run `python tools/lumen.py validate`, `python -m unittest discover -s tests -v`, and `node --test tests/settings-model.test.mjs` before generating patches. Build and test affected upstream components for browser behavior changes. Do not interpret green tooling/model suites as successful Firefox validation. New upstream pins require refreshed source snapshots and SHA-256 entries, review of removed/renamed preferences, configure interfaces and tests, regenerated patches, security advisory review, and the packaged verification matrix.

Git and Python standard library suffice for patch/bundle tooling; Node 20+ runs settings-model tests without npm packages. Firefox prerequisites and commands are in BUILDING.md. No project registration, paid component, runtime daemon, or additional package dependency is required for these tools. Tool logs and captures stay local; sanitize before sharing. Do not add CI uploads of profiles, captures or credentials. Foundation CI is configured; browser release automation is not.

GitHub Actions foundation checks run validation, Python and JavaScript tests, patch generation, and reproducible source packaging on Windows and Linux. Linux CI tests tooling only; it does not imply a Linux browser port. No test captures, profile data, or browser artifacts are uploaded. The checkout action is pinned by commit and uses read-only repository permission with credential persistence disabled.

`config/preferences.json` defines shipped default overrides. `config/customization.json` defines curated controls and does not silently change defaults. `browser/settings-model.mjs` contains platform-independent validation/recovery. `browser/settings.js` is the privileged adapter in the existing Firefox settings page; it must accept writes only through the allowlisted model. Generated localization lives under upstream's en-US resources. Other locales need translations and fallback verification before support is advertised. Follow DELIVERY_PLAN.md and PRODUCT_GOALS.md when selecting new work.

Use deterministic output, bounded subprocess timeouts, actionable errors, safe path handling, and atomic artifact writes. The generator's outputs belong under `out/` when inside this repository. Never edit `sources/` in the enclosing project or change the unrelated Meridian repository. Preserve Windows 10+ compatibility when modifying native code or dependencies.
