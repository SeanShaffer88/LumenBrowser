# Privacy status and initial network inventory

**Packaged Lumen Browser development builds have launched in disposable Windows 11 profiles. Process-attributed traffic capture has not been performed; zero telemetry is not established.** The table is a preliminary inventory of Firefox service classes, not an exhaustive endpoint or code-path audit. Transmitted fields below describe expected categories; payload schemas, timing, and regional variants need pinned-source tracing and runtime confirmation. Every remote service sees some network metadata, usually the connecting IP and request timing.

The source patch sets defaults; existing profile values, policies, experiments, extensions, or future upstream code can override behavior. Native compilation has succeeded with the development flags; their complete privacy effects are not established. Legacy telemetry and Glean are separate audit surfaces ([Mozilla telemetry documentation](https://firefox-source-docs.mozilla.org/toolkit/components/telemetry/)).

Remote Settings includes security consumers; its removal is not a substitute for identifying nonessential consumers ([upstream service documentation](https://firefox-source-docs.mozilla.org/services/settings/index.html)). Unlike [LibreWolf's documented Safe Browsing choice](https://librewolf.net/docs/features/), Lumen's candidate retains that security mechanism. This comparison is limited to that published design choice.

Pinned-source tracing found that `ExperimentAPI.labsEnabled` depended on enterprise policy allowance, independently of the studies/upload preferences. `RemoteSettingsExperimentLoader.enable()` checks `ExperimentAPI.enabled`, which is the union of Labs/rollout/study gates. The patch disables those three optional experiment gates explicitly rather than disabling Remote Settings as a whole. The generated browser test passed and checks the resulting disabled state. Browser Glean remains compiled and must be audited separately; disabled upload defaults and build reporting flags are not proof that all measurement code is absent.

## Local data

Repository tooling reads the pinned snapshots and configuration to generate patches, source bundles and original branding assets under their documented output directories. The native packager compiles and brands a temporary self-extractor using the local Windows toolchain. These tools do not inspect personal browser profiles or send telemetry. Build/bootstrap and upstream metadata retrieval contact their documented upstream services. Runtime verification uses owned disposable profiles and local logs; raw logs, profiles and captures are excluded from source bundles. No personal browser history, credentials or crash dumps are test inputs.

The browser retains upstream profile storage, password encryption, cookie storage, and history semantics pending review. Private browsing does not provide anonymity or guaranteed forensic erasure. Extension privacy behavior is outside the scope of these default preferences. Password CSV exports are plaintext: use upstream's explicit warning and avoid exporting for tests.

The implemented settings editor exports only values from its 57-entry allowlist. It cannot export arbitrary profile preferences, passwords, cookies, history, bookmarks or file paths. Import is local, versioned and size-bounded; it previews changes and warnings and respects policy locks. Unsupported custom values are reported as omitted during export. Native controls tests cover both Preferences layouts, while independent model tests cover import/write/rollback failure handling. Complete packaged import/export and accessibility qualification remain open.

## Runtime regional defaults

Native default assertions found that Quick Suggest recalculates defaults by region/locale after loading firefox.js, re-enabling its platform and sponsored suggestions on the test host. The patch now makes the intended regional defaults for platform, sponsored and nonsponsored suggestions false. It retains default-branch handling and user choices rather than locking preferences or disabling security Remote Settings consumers. All 31 configured defaults and both Nimbus gates pass the native test after startup. This still does not establish absence of collection or network traffic.
